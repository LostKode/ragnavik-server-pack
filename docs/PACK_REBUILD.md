# Complete pack rebuild

This branch rebuilds `LostKode-Ragnavik_Server` from first-wave commit `14402f1`.
Hexium is the primary source. Dependencies that remain exclusive to Thunderstore are retained so Gale can resolve the mixed profile.

## Client coordination contract

`manifests/client-manifest.json` is a proposed dependency snapshot for the separate client task. It does not edit or version the client repository. The client task must consume the same server pin, preserve the listed client-only packages, and verify its installed DLL and GUID inventory before release.

`manifests/package-inventories.json` contains normalized before and proposed server dependencies, client direct and effective dependencies, config files, plugin files, patchers, and assets. It is generated by `scripts/generate_inventories.py` and validated in CI.

## Consolidated packages

`LostKode-Ragnavik_Compatibility-0.1.0` replaces the standalone EpicMMO reload guard. `LostKode-Ragnavik_Server_Bridge-1.0.0` replaces the separately mounted Progress and Catos Reporter components. Their versions and GUIDs come from the completed first-wave worktrees. Neither package is published by this branch.

## Unresolved release gates

* The existing Ragnavik Max Dungeon Rooms configuration is not present in the source history or readable live source tree. The dependency remains pinned at `Digitalroot-Max_Dungeon_Rooms-2.0.39`, but publication and deployment are blocked until the authoritative configuration is recovered and added.
* MaxPlayerCount is pinned at `Azumatt-MaxPlayerCount-1.2.5`, but its generated configuration schema is not bundled upstream. The approved value is 15. Publication and deployment are blocked until that exact generated key is captured from a test profile and committed.
* The compatibility and server bridge packages are represented at their evidenced versions, but those packages must be published or otherwise made resolvable before Gale or Hexium can install this package.
* The separate client task must confirm its release version and accept the proposed client snapshot before anti-cheat policy is treated as release-ready.

No package is published and no production service is changed by this branch.
